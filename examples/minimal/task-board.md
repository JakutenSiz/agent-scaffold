# Task Board — minimal-example

> **Canonical task list.** Work is picked from here first. Closed items move to
> `task-board-archive.md` (never deleted). No hand-written derived views: a filtered view is
> generated by a script and never committed. Size sentinel: `node scripts/md-size-watch.mjs`
> (ceiling 4000 lines — archive, do not trim).

## Status markers

| Marker | Meaning |
|---|---|
| 🔴 Open | not started or in progress |
| 🟡 Partial | part shipped, remainder listed under **Remaining** |
| 🔵 External | waiting on a third party (store review, provider approval, vendor) |
| 🧪 Smoke pending | code done, live/smoke evidence missing |
| ⏸️ Deferred | intentionally parked; reason in **Decision/blocker** |
| ✅ Done | closed, evidence in **Last evidence**; moves to archive |
| 🟢 Live | shipped and observed in production |
| 🔬 Research | discovery only, output goes to `reports/` |
| ℹ️ Info | not a task; a pinned fact or policy |

## Who may do what?

Every open item carries one tag:

- `[DEV]` — only the project owner may do the remaining step: destructive or structural data changes, deleting data, changing auth or billing, unresolved architectural decisions, anything with a real-money or legal consequence.
- `[ANY]` — anyone, including an AI agent, may do it end to end.

Rules: the tag reflects the **remaining** work, not the whole scope. When unsure, `[DEV]`. An item may be escalated mid-flight when a destructive need appears. Closed items carry no tag.

## §9 Update rules (read before editing this file)

### 📐 Compact item template

```
### <code> <status> [DEV|ANY] <title — the item's identity; references point here>
**Remaining:** concrete work still to do (which repo/file/endpoint; if a human step, name who)
**Last evidence:** one line — date + sha / release / measurement
**Human step:** [OWNER] one sentence, optional (YYYY-MM-DD) date · [OWNER] next person's step (omit the line when no human is needed)
**Decision/blocker:** only what is STILL in force (owner decision, external approval, flag state)
**Trap:** ≤ 3 lines — what goes wrong if you do not know it (env name, order, silent failure)
**Full history:** `task-board-archive.md § <code>`
```

- **Replace evidence, do not append eras.** Old evidence goes to the archive under the same code; the live item shows only the current state.
- **Body ≤ 20 lines** (≤ 35 when it lists 5+ concrete sub-tasks).
- **Update the `###` heading in the same edit as the body.** Title and body go stale independently; a heading that still says 🔴 over a body that says "shipped" is the most common rot.
- **Never open a new `##`/`###` for a sub-note.** Sub-notes go into the item's fields or into the archive.
- **Look at the code before starting or closing an item.** The claim in the item is verified against the repo, not trusted.
- **Duplicate check before adding:** run `node scripts/board-duplicate.mjs "<keyword>"` (recent commits, board and archive matches, code free or taken) and check the coordination file — a concurrent session may already have written the same finding. If so mark yours `↪ DUPLICATE — see <code>` instead of adding a twin.
- **Human step expiry:** the **Human step** field is the only thing `node scripts/human-queue.mjs` reads (one queue per `[TAG]`). A step older than 4 weeks is flagged EXPIRED; the human then supplies evidence or the item is deferred (⏸️). Scripts never drop an item.
- **Lint at commit:** `node scripts/board-lint.mjs --staged` checks the items you changed (completion line added without a heading/Remaining change, appended eras, duplicate codes, heading vs Remaining mismatch). Mode and escape come from the project config (`board.lint`).

### 🔢 Item codes

New items use `<MMDD>-<short-slug>` (e.g. `0918-gate-baseline`), never a sequential number that two sessions could both pick. If a code collides, the first user keeps it; never renumber.

### 🚫 No derived views

No second hand-maintained status file. If a filtered view is needed, a script generates it and it is not committed.

### 📦 Archive discipline

A closed item's full text moves to `task-board-archive.md`: run `node scripts/board-archive.mjs` (dry run), then `--write`. Items whose heading is ✅ and whose **Remaining** carries no owner tag move verbatim — each keeps its `### <code>` heading under a dated closure section, so `§ <code>` references still resolve with a search. A ✅ item that still carries tagged work stays and is reported. Never move items by hand and never trim open ones.
